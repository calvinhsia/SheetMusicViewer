# Development Guide

## Requirements

| Tool | Version |
|---|---|
| [.NET SDK](https://dotnet.microsoft.com/download) | 10.0 or later |
| [Visual Studio](https://visualstudio.microsoft.com/) | 2022 17.x+ (Community edition is sufficient) |
| Windows | Required for the WPF project and WPF-targeted tests; the Avalonia project builds on any OS |

## Getting Started

```powershell
git clone https://github.com/calvinhsia/SheetMusicViewer
cd SheetMusicViewer

# Restore packages and build everything
dotnet build

# Run the app (Avalonia, cross-platform)
dotnet run --project SheetMusicViewer.Desktop
```

Or open `SheetMusicViewer.sln` in Visual Studio and press **F5** with **SheetMusicViewer.Desktop** as the startup project.

## Running Tests

> **Important**: Always filter tests to exclude `Manual` tests unless you explicitly intend to run them. Manual tests can modify source files (e.g., regenerating `GettingStarted.pdf` and `GettingStarted.json`) or require special setup.

```powershell
# Recommended — Unit tests only (fast, safe)
dotnet test --filter "TestCategory=Unit"

# Unit + Integration (excludes Manual)
dotnet test --filter "TestCategory!=Manual"

# Single test by name
dotnet test --filter "FullyQualifiedName~MyTestMethodName"

# Specific project
dotnet test Tests --filter "TestCategory=Unit"
```

### Test Categories

| Category | Description | Safe to run? |
|---|---|---|
| `Unit` | Fast, isolated; no file system or UI | ✅ Always |
| `Integration` | Uses file system or multiple components | ✅ Safe |
| `Manual` | Modifies source files, requires user interaction, or has side effects | ⚠️ Only when explicitly requested |

## Code Organisation Conventions

### Re-entrancy guards

Use `try/finally` to ensure guard flags are always reset:

```csharp
private bool _isHandling;

private void OnSomeEvent()
{
	if (_isHandling) return;
	_isHandling = true;
	try
	{
		// code that might throw or trigger re-entrant calls
	}
	finally
	{
		_isHandling = false;
	}
}
```

### Adding unit tests for bug fixes

When fixing a bug always add a corresponding unit test:

- Re-entrancy issues → test that the guard works correctly including exception scenarios
- Collection mutation errors → simulate the cascading event pattern
- UI event handling → test keyboard shortcuts (Enter/Escape) and event handlers

Tag the test with `[TestCategory("Unit")]`.

## Adding a New Feature

1. Put platform-independent logic in `SheetMusicLib`
2. Put Avalonia UI code in `SheetMusicViewer.Desktop`
3. Add unit tests in `Tests` (for library code) or `AvaloniaTests` (for Avalonia UI code)
4. Run `dotnet test --filter "TestCategory!=Manual"` before committing

## Publishing

```powershell
# Self-contained Windows x64 executable
dotnet publish SheetMusicViewer.Desktop -c Release -r win-x64 --self-contained

# Or use the included publish profile
dotnet publish SheetMusicViewer.Desktop -p:PublishProfile=FolderProfile-win-x64
```

The output is placed in `SheetMusicViewer.Desktop\bin\Release\net10.0\win-x64\publish\`.

## Sample Music Assets

`GettingStarted.pdf` and `GettingStarted.json` in `SheetMusicViewer.Desktop\Assets\SampleMusic\` are bundled with the app and installed on first launch by `SampleDataHelper`. These files are regenerated by the `GenerateGettingStartedPdf` Manual test — only run that test intentionally.
